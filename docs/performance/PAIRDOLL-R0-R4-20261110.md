## Findings

1. PairDoll has two distinct Elementor `slides` widgets: desktop widget `6287346` (autoplay 5,000ms; hidden on mobile), mobile widget `9c0199b` (autoplay 3,000ms; hidden on desktop/tablet). The mobile Lighthouse LCP candidate is a carousel background `Photo-album-banner-correct-size.jpg`, with 6.55–7.55s of element render delay. Carousels may update LCP long after the initial useful paint.
2. LiteSpeed option readback: `litespeed.conf.guest=1`, `litespeed.conf.guest_optm=1`, `litespeed.conf.optm-guest_only=1`. Public HTML issues `guest.vary.php` and can trigger `window.location.reload(true)` for a fresh visitor. Mobile Lighthouse redirect opportunity estimated 3.48–5.89s. It is a diagnostic clue, **not proof** that all real visitors incur that delay.
3. LCP JPEG `Photo-album-banner-correct-size.jpg` ~573KiB; logo `PAIRDOLL-LOGO.png` ~177KiB is displayed around 100 × 50. Lighthouse flags image-delivery savings. Verify optimized equivalents and visual parity before any URL or media metadata switch.
4. TBT is already 0ms and desktop performance 95. Global JS stripping, CSS removal, or a second page cache is unjustified.

## R2 actual A/B results — 2026-11-10

Independent macOS Chrome Lighthouse 12.6.1 mobile simulations, three sequential runs, baseline same URL and flags. Scores are **Lighthouse CLI**, not Google PageSpeed Insights or GTmetrix.

| LiteSpeed configuration | Mobile scores | Median | LCP (s) | Median LCP |
| --- | --- | ---: | --- | ---: |
| Guest Mode ON, Guest Optimization ON (original) | 73, 70, 69 | **70** | 7.2, 7.2, 8.6 | **7.2** |
| Both OFF (short-lived test) | 62, 66, 67 | 66 | 15.2, 10.2, 10.5 | 10.5 |

A/B verdict: **Guest OFF rejected**. Both WordPress options were restored to `1`, and `wp litespeed-purge url https://pairdoll.com/` completed. Original readback: `guest=1`, `guest_optm=1`, `optm-guest_only=1`. This is a performance experiment only; no checkout/payment cache policy was changed.

Separate **browser-local request interception** (not deployed) confirmed exact mobile Elementor widget setting was patchable to `autoplay=no`. For the mobile hero, replacing the original 585 KB JPEG with the verified R2 WebP plus a mobile-only preload yielded two observed browser PerformanceObserver LCP entries at ~1.424s and ~1.432s, with the actual WebP URL as LCP. In baseline and autoplay-only runs, LiteSpeed lazy placeholders often remained the final LCP, making this comparison **non-equivalent**. It is a mechanism smoke test, **not proof of production speed uplift or PageSpeed 90+**.
